# Q-SHIELD — Scientific & Viva Defense Claim Guidelines

This document categorizes all academic, technical, and viva defense claims into **SAFE TO SAY**, **CAUTION / QUALIFY**, and **DO NOT SAY**.

---

## 1. SAFE TO SAY (Defensible Claims)

1. ✅ **"Q-SHIELD implements an end-to-end software simulation of the BB84 QKD protocol including state preparation, sifting, pre-reconciliation QBER calculation, error reconciliation, and privacy amplification."**
2. ✅ **"The Stage 3 AI Anomaly Detector uses an unsupervised Isolation Forest model trained exclusively on physical/statistical channel telemetry over 10-qubit rolling windows, obeying strict zero-label feature isolation."**
3. ✅ **"Stage 4 Post-Quantum Authentication uses NIST FIPS 204 ML-DSA-65 digital signatures to protect classical basis reconciliation messages against active Man-in-the-Middle (MITM) tampering, with an average measured session overhead of 59.86 ms."**
4. ✅ **"The Stage 5 Hybrid Security Decision Engine synthesizes QBER (25%), AI anomaly (30%), PQC authentication (30%), and physical telemetry health (15%) with a mandatory 11% QBER critical security override."**
5. ✅ **"Under 50 simulated clean baseline evaluation trials, the AI detector achieved a 0.00% False Positive Rate."**
6. ✅ **"ML-DSA-65 classical authentication achieved a 100% block rate against active MITM message tampering across evaluation sweeps."**
7. ✅ **"The complete backend unit test suite passes with 80/80 tests, and the frontend compiles with zero TypeScript errors."**

## 2. CAUTION / QUALIFY (Requires Context / Qualification)

1. ⚠️ **"Privacy Amplification Uses SHA-256 Truncation"**  
   *Qualify as*: "SHA-256 truncation is implemented as a practical hash-based compression abstraction for software simulation purposes, whereas formal QKD theoretical security proofs utilize universal hash families (Toeplitz matrices)."
2. ⚠️ **"Channel Noise Model"**  
   *Qualify as*: "The channel noise model is a Simulated Orthogonal State-Flip Noise Model ($|0\rangle \leftrightarrow |1\rangle$, $|+\rangle \leftrightarrow |-\rangle$), rather than full density matrix numerical integration or Kraus operator open-system master equations."
3. ⚠️ **"Derived Secret Key vs Policy Approval"**  
   *Qualify as*: "The system derives secret key material mathematically via BB84 processing, but downstream policy enforcement labels the key status as `APPROVED BY SECURITY POLICY` or `REJECTED BY SECURITY POLICY` based on hybrid security assessment."

## 3. DO NOT SAY (Unjustified / Misleading Claims)

1. ❌ **"PQC ML-DSA-65 overhead is <1 ms per quantum round."**  
   *Reason*: Measured session-level authentication overhead is **59.86 ms** and applies to classical basis reconciliation frames, not individual quantum rounds.
2. ❌ **"The generated key is unconditionally secure under theoretical QKD proof."**  
   *Reason*: Software hash-based privacy amplification does not satisfy unconditional security proofs.
3. ❌ **"ML-DSA-65 protects the quantum states in transit."**  
   *Reason*: Quantum states cannot be signed or modified without collapse. ML-DSA-65 authenticates the classical communication channel.
4. ❌ **"The AI detector is trained on real physical hardware measurements."**  
   *Reason*: The AI model is trained on simulated physical channel telemetry generated by software models.
5. ❌ **"The simulation incorporates physical single-photon avalanche diode (SPAD) noise."**  
   *Reason*: Telemetry signals are behavioral software abstractions of detector parameters.
